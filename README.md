# Обнаружение и тушение лесного пожара

Консольное приложение на C, моделирующее обнаружение и тушение лесного пожара. Модель дискретная, тактовая, последовательная.

Программа отвечает на вопрос: **«при таком расположении пожарной станции — за сколько тактов пожар будет потушен?»** Режим `--station-scan` перебирает все кандидаты станции из карты и находит лучший.

## Возможности

- клеточная карта: трава, дерево, вода, ров;
- распространение огня с учётом растительности, ветра и возраста горения;
- датчики (а также станция и пожарные группы) сообщают об очагах в центр; сообщения могут задерживаться, теряться и дублироваться;
- координационный центр создаёт задачи и назначает ближайшие свободные группы;
- группы движутся (BFS), тушат очаги и сами берут соседние цели без возврата на станцию;
- цветной вывод в терминале (ANSI, 256 цветов), один `write` на кадр;
- воспроизводимые прогоны (`--seed`) и перебор позиций станции (`--station-scan`).

## Требования

- Linux / macOS (POSIX-терминал с поддержкой ANSI);
- компилятор C (gcc или clang);
- `make` (если в проекте есть `Makefile`).

## Сборка

```bash
make
```

Исполняемый файл появится в `build/fire`.

## Запуск

```bash
./build/fire [опции]
```

### Аргументы

| Аргумент | Значение |
|---|---|
| `--map FILE` | Файл карты (**обязателен**) |
| `--conditions FILE` | Файл конфигурации (по умолчанию `data/conditions.conf`) |
| `--station R C` | Станция в позиции (R, C), 0-индексно |
| `--station-scan` | Перебрать всех кандидатов станции из карты |
| `--seed N` | Seed генератора случайных чисел (воспроизводимость) |
| `--delay MS` | Задержка между тактами, мс |
| `--quiet` | Без отрисовки кадров (для пакетных прогонов) |
| `--no-ansi` | Отключить ANSI-раскраску |

### Примеры

Одиночный прогон:

```bash
./build/fire --map data/map_big_01.map --station 9 15 --delay 200
```

Воспроизводимый прогон:

```bash
./build/fire --map data/map_lake.map --station 7 4 --seed 42 --delay 100
```

Перебор всех кандидатов станции:

```bash
./build/fire --map data/map_big_01.map --station-scan --seed 42
```

С другим конфигом:

```bash
./build/fire --map data/map_lake.map --conditions data/conditions_dry.conf --station-scan --seed 42
```

### Управление

| Клавиша | Действие |
|---|---|
| `q` | завершить текущий прогон (или весь перебор) |
| `Ctrl+C` | то же; терминал восстанавливается корректно |

### Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | общая ошибка |
| 2 | неверные аргументы |
| 3 | ошибка в конфиге |
| 4 | ошибка в карте |
| 5 | ошибка инициализации мира |
| 130 | прервано по Ctrl+C |

## Результат работы

На каждом такте выводятся шапка (такт, ветер, огонь, потушено, выгорело, в пути, в инбоксе), строка задач, цветная карта и последние 5 событий. По завершении печатается итог: результат, число тактов, seed, статистика карты, задач, групп и сообщений.

Коды результата:

| Код | Условие |
|---|---|
| `EXTINGUISHED` | нет горящих клеток |
| `TERRITORY_EXHAUSTED` | всё, что могло гореть, выгорело |
| `TICK_LIMIT` | исчерпан `end.max_ticks` |
| `INTERRUPTED` | прервано пользователем |

Пример вывода `--station-scan`:

```text
Перебор 4 позиций станции (seed = 42)...

  ( 7, 4): EXTINGUISHED          84 тактов  выгорело  55  потушено  42
  ( 7,15): EXTINGUISHED         102 тактов  выгорело  71  потушено  35
  ( 3,10): TICK_LIMIT           500 тактов  выгорело 198  потушено  12
  (15,10): TERRITORY_EXHAUSTED  220 тактов  выгорело 230  потушено   8

Лучшая станция: (7,4), ликвидация за 84 тактов
```

## Файл конфигурации

Формат `ключ = значение`, комментарии начинаются с `#`. Ошибки выводятся как `файл:строка: сообщение`.

```ini
fire.base_prob_grass       = 0.15
fire.base_prob_tree        = 0.20
fire.burn_time_factor      = 1.5
fire.wind_factor_along     = 1.8
fire.wind_factor_against   = 0.4
fire.wind_factor_side      = 1.0
fire.spread_8dir           = true
fire.reburn_burnt          = false

wind.direction             = SE      # N NE E SE S SW W NW
wind.power                 = 2

sensor.radius              = 2
sensor.resend_period       = 5

msg.delay_min              = 1
msg.delay_max              = 3
msg.loss_prob              = 0.10
msg.dup_prob               = 0.05

team.count                 = 5
team.speed                 = 2
team.extinguish_time       = 3
team.efficiency            = 1.0
team.return_to_station     = false
team.can_cross_water       = false
team.can_cross_firebreak   = true

end.max_ticks              = 600
end.unlimited              = false
```

## Файл карты

Секции: `size`, `terrain:`, `ignition:`, `sensors:`, `station_candidates:`.

```text
size = 16 20

terrain:
w"""""""""""""""""""
w"""ttt""""""ttt""""
...

ignition:
2 5
2 14

sensors:
4 2
4 17

station_candidates:
7 4
7 15
```

Обозначения клеток: `"` — трава, `t` — дерево, `w` — вода, `_` — ров.

Проверки парсера: длины строк `terrain`, очаг не на воде/рве, кандидат станции не на воде, координаты внутри карты.


## Структура проекта

```text
src/
  main.c       разбор аргументов, диспетчер режимов
  config.c/.h  чтение conditions.conf
  map.c/.h     чтение map_*.map
  world.c/.h   состояние мира
  sensors.c/.h наблюдение датчиками
  messages.c/.h очередь сообщений (задержка, потери, дубликаты)
  center.c/.h  координационный центр
  teams.c/.h   движение, тушение, возврат групп
  fire.c/.h    распространение огня
  sim.c/.h     тактовый цикл, условия завершения
  render.c/.h  отрисовка кадра
  term.c/.h    ANSI, termios, сигналы
  log.c/.h     кольцевой буфер событий (512 записей)
data/          карты и конфиги
tests/         тестовые скрипты
```

### Порядок фаз такта

1. наблюдение (датчики и группы);
2. передача сообщений;
3. решения центра;
4. перемещение групп;
5. тушение;
6. распространение огня;
7. публикация состояния.

## Известные ограничения

- Огонь может обогнать группы при высоких `base_prob_*` и малом `team.count` — это штатное поведение модели.
- Группа, окружённая огнём, может застрять (BFS не находит путь).
- Проверка выхода огня за границу карты удалена; `RESULT_OUT_OF_BOUNDS` оставлен в `enum` для совместимости, но не возвращается.
- Лог событий хранится только в памяти; CSV-отчёт не реализован.
